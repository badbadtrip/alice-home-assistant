# Алиса для Home Assistant

Колонки Алисы, точные голосовые команды и управление мостами в одном приложении HA.
Встроенное руководство работает без интернета: подключение колонки, установка моста,
настройка фраз, обновление и восстановление.

**Экспериментальная версия 0.8.2.** Неофициальный проект; не связан с Яндексом.
Проверено на Home Assistant OS amd64 с MIDI и Lite 2. Установка на других
моделях/прошивках и нативная сборка на aarch64 требуют отдельной проверки.

[![Добавить репозиторий в Home Assistant](https://my.home-assistant.io/badges/supervisor_add_addon_repository.svg)](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2Fbadbadtrip%2Falice-home-assistant)

## Установка

1. В HA откройте **Настройки → Приложения → Установить приложение**.
2. В меню справа выберите **Репозитории** и добавьте:
   `https://github.com/badbadtrip/alice-home-assistant`.
3. Найдите **Алиса** в разделе этого репозитория и нажмите **Установить**.
   Контейнер собирается на устройстве HA из исходников; первая сборка займёт время.
4. Запустите приложение, включите показ в боковом меню и откройте веб-интерфейс.
5. Добавьте колонку. В мастере «Настройки → Мост» введите локальный адрес Home
   Functions, например `http://192.168.10.10:18080`, и нажмите **Сохранить и продолжить**.
   Адрес запишется в настройки, приложение автоматически перезапустится.
6. Продолжите настройку доступа и подключение моста по следующим шагам мастера.

Требуются Home Assistant OS с Supervisor, права администратора, совместимая
ARM64-колонка с заранее настроенным root SSH и доступ HA к ней по локальной сети.
Приложение не получает root и не прошивает колонку. Для громкости и озвучивания
нужна настроенная интеграция Яндекс Станций и сущность `media_player`.

Каждая новая установка создаёт собственный SSH-ключ, токен и пустой реестр колонок.
Рабочие ключи, реестры и настройки пользователей в репозитории отсутствуют.
Точные команды хранятся в метаданных HA: существующие фразы в том же HA могут
появиться сразу, даже если реестр колонок пуст.

## Повторная установка рядом с локальной версией

Установка из GitHub — отдельное приложение с отдельными данными. Не импортируйте
старый реестр, если хотите проверить ручную настройку. Чтобы оставить рабочую
локальную версию включённой, задайте новой установке другой внешний порт, например
`18081`, и `advertised_url` с тем же портом. Панели этих установок изолированы.
Подключайте станции к новому экземпляру по одной, с резервной копией и голосовой
проверкой; остальные станции могут продолжать работать через прежний экземпляр.

## Разработка

Каталог `alice/` содержит **полный самостоятельный Docker-контекст**. Для сборки
из клона соседние проекты не нужны:

```sh
docker build -t alice-ha-app:0.8.2 ./alice
python -m unittest discover -s tests -v
python tools/check_release.py
```

`tools/prepare.py` — инструмент сопровождающего для повторного импорта изменений
из исходного рабочего дерева; он требует соседние исходники и не нужен для
установки или Docker-сборки опубликованного репозитория.

Исходное авторство, лицензии и ссылки на проекты сохранены в [NOTICE](NOTICE),
`alice/bridge/LICENSE` и `alice/bridge/THIRD_PARTY_NOTICES`.
