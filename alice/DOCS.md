# Установка приложения

## Что потребуется

- Home Assistant OS, права администратора и место для сборки контейнера.
- Хост HA на amd64 или aarch64; стабильный локальный адрес HA.
- Совместимая ARM64-колонка с уже настроенным root SSH.
- Для громкости, воспроизведения и озвучивания — настроенная интеграция Яндекс
  Станций с рабочей сущностью media_player для каждой колонки.

## Установка из GitHub

1. Откройте Настройки → Приложения → Установить приложение.
2. В меню справа выберите «Репозитории» и добавьте URL:

```text
https://github.com/badbadtrip/alice-home-assistant
```

3. Найдите «Алиса» в разделе добавленного репозитория и нажмите «Установить».
4. Дождитесь завершения сборки и откройте настройки приложения.
5. Задайте локальный адрес Home Functions, запустите приложение и включите
   показ в боковом меню. Откройте веб-интерфейс и руководство подключения колонки.

## Локальная установка для разработчиков

Подготовленный каталог `alice` также можно скопировать в `/addons/alice`
на HA через SSH/Samba, обновить магазин и установить локальное приложение.
Каталог приложения содержит все исходники; это не интеграция custom_components.

## Две установки рядом

Локальное приложение и приложение из GitHub имеют разные ключи и реестры.
Для одновременной работы измените внешний порт новой установки на свободный,
например `18081`, и укажите этот же порт в advertised_url. Их панели не
перезаписывают друг друга. При ручной настройке не импортируйте старый реестр.
Существующие команды могут оставаться видимыми: они хранятся в самом HA.

## Настройка

`advertised_url` — адрес, по которому КОЛОНКА сможет обратиться к приложению.
Например, если IP хоста HA `192.168.10.10`, а внешний порт приложения `18080`:

```text
http://192.168.10.10:18080
```

Это не внешний HTTPS-адрес HA и не адрес Ingress. Колонки и хост HA должны
достигать друг друга по LAN. Если внешний порт изменён во вкладке «Сеть»,
укажите тот же порт в advertised_url. Не публикуйте этот порт в Интернет.

`speaker_network` — допустимая подсеть колонок в CIDR. Например `192.168.10.0/24`.
Значение `0.0.0.0/0` разрешает все частные IPv4-подсети; публичные адреса,
loopback и имена хостов менеджер всё равно отклоняет.

`voice_command_label` — ID метки для автоматизаций и скриптов голосовых команд.
По умолчанию `alice_voice_commands`. Приложение создаёт метку при первом запуске.

`device_labels` — ID меток устройств, доступных Home Functions. По умолчанию
`alice`. Назначайте эту метку сущностям HA, которыми нужно управлять голосом.

Поля `llm_base_url`, `llm_model`, `llm_api_key` необязательны, но заполняются
вместе. Пока они пустые, остальные запросы отправляются штатной Алисе.

Запустите приложение, включите автозапуск и откройте веб-интерфейс. После изменения
параметров перезапустите приложение. При обновлении UI обновите браузер без кеша.

## Первый запуск

Приложение создаст уникальный SSH-ключ и случайный токен Home Functions.
Данные сохраняются в `/data`; повторный запуск не меняет ключи и токен.
Создаётся отдельная скрытая панель для этого экземпляра приложения; чужие панели не перезаписываются.

Откройте [установку моста](Bridge.md) и подключите первую колонку.
