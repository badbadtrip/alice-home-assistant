# 7. Мост: структура и конфигурация

Код: `alice/bridge/cmd/quasar-bridge/main.go` (531 строка), `config.go`, `internal/*`.

## Наблюдения

- `main.go` — всё в одной функции: флаги диагностики, наблюдатель кадров, LLM-клиент, два бэкенда дома, ассистент, журнал, голосовые реплики, AirPlay, Sendspin, здоровье, метрики, LAN-сервер, отчёт состояния, перезагрузка маршрутов.
- Два бэкенда дома: `home.Controller` через MCP (`QUASAR_HOME_MCP_URL`, прогрев `home_warm_area` раз в минуту) и `home.Functions` (HF). Поставка использует только HF; MCP-путь встречается лишь в примерах конфигов.
- Режимы `observe` и `hybrid`; поставка — `hybrid`. `observe` — наследие отладки.
- `-speaker-endpoint` правит прошивку (`quasar.cfg`) — опасный путь, при read-only корне не нужен.
- `/music-state` — менеджер сообщает мосту, играет ли штатная музыка (из HA, `updater.py:166`). Третий источник «музыка играет» для кольца (см. 3.4).
- Код отформатирован по-разному: часть файлов в стиле «одна строка» (`voice_cache.go`, `telemetry/activity.go`), `gofmt -l` показывает ~18 файлов.
- Пример `config.example.json` расходится с поставкой `alice/bridge-config.json` (`default_route`, правила).

## Задачи

### 7.1 Разрезать `main.go`
- `wire.go` (сборка зависимостей), `health.go` (состояние/метрики), `players.go` (AirPlay, Sendspin, текущий трек), `diagnostics.go` (флаги). Поведение не меняется; цель — видно, что запускается и в каком порядке.

### 7.2 Убрать неиспользуемое
- Решить с пользователем: MCP-бэкенд дома (`home.Controller`, `home_warm_area`), режим `observe`, `-speaker-endpoint`. Если не нужны — удалить с тестами и примерами. Меньше кода — меньше путей в `Decide`.

### 7.3 Один формат кода
- `gofmt` на весь модуль отдельным коммитом без изменений логики; в CI — проверка `gofmt -l` (на Linux, где нет CRLF).

### 7.4 Конфиг: одна правда
- Пример конфига генерировать из поставки или удалить, оставив `alice/bridge-config.json` с комментариями в Wiki.
- Значения по умолчанию в коде (`DefaultRoutingConfig`) = поставка (см. 2.4).

### 7.5 Наблюдатель кадров
- `Proxy.Observer` логирует каждый не-аудио кадр (`slog.Info("frame", ...)`) — на слабой колонке это постоянная запись в журнал. Оставить счётчики, детальный лог — только при включённой диагностике.
