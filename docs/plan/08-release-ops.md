# 8. Сборка, релиз, журналы

## Наблюдения

- Две копии: `CHANGELOG.md` и `alice/CHANGELOG.md`, `wiki/` и `alice/wiki/`; `tools/sync_release.py` синхронизирует, `alice/source-manifest.json` пересчитывается на каждый релиз (SHA-256 232 файлов). Каждый релиз трогает 4–5 файлов кроме кода.
- Журнал приложения HA забит сообщениями TRACE/DEBUG библиотеки HF (`[TRACE][hass:call] loadServiceList`, списки всех сервисов HA при старте). Полезные строки (sendspin, Exposed) теряются.
- CI: `check.yml` (тесты), `image.yml` (образ), `promote.yml` (fast-forward `main`). Ветка, чей коммит уже в `main`, пропускает `image` фильтром путей — запуск вручную.
- Тест Go `TestVoiceCuesPersistOnlyCompleteOpus` падает на Windows (права файлов), в CI на Linux проходит.

## Задачи

### 8.1 Одна копия документов
- Корневые `CHANGELOG.md`/`wiki/` сделать единственным источником; в образ копировать при сборке (`Dockerfile COPY`), а не хранить вторую копию в `alice/`. Если Supervisor требует файлы в `alice/` (CHANGELOG для окна обновления) — генерировать в CI, не руками.
- Манифест — проверять в CI, пересчитывать скриптом в pre-commit, а не вручную.

### 8.2 Уровень логов
- HF: уровень `info` по умолчанию (библиотека `@digital-alchemy` — настройка `LOG_LEVEL`/конфиг boilerplate), TRACE — только по опции приложения `debug: true`.
- Менеджер и music: единый формат «компонент: сообщение», без секретов.

### 8.3 Проверки одной командой
- `tools/check.sh` (или `make check`): Python-тесты, `pnpm lint/typecheck/test`, `go test ./...`, `check_release.py`. То же в CI. Сейчас команды разбросаны по `AGENTS.md`.

### 8.4 Поставка моста
- Мост собирается в образе приложения и раздаётся менеджером. Хранить хеш собранного моста в `BUILD-REPORT.md` автоматически из CI.
