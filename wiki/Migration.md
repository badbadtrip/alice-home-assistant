# Перенос существующей установки

Чистая установка приложения не импортирует чужой мост автоматически. Для
миграции менеджера на другом сервере нужен отдельный перенос приватных данных.

## Если мастер остановился на старом мосте

SSH-проверка подтверждает только доступ к колонке. Она не переносит прежний
мост, его настройки и записи об установке в новое приложение.
Если приложение сообщает, что мост установлен другой установкой, обновление
остановлено. Повторное нажатие «Установить» не поможет. Не удаляйте работающий
мост и не создавайте подтверждение установки из случайных файлов колонки.

Нужен перенос из прежнего менеджера с проверенными данными установки.
Автоматического переноса из этого окна пока нет. Описанный ниже офлайн-импорт
предназначен только для пустого реестра. Если колонки уже добавлены вручную,
не накладывайте архив поверх них: сначала сохраните текущую конфигурацию
и подготовьте отдельный план переноса с администратором прежней установки.

## Что необходимо сохранить

- SSH-ключ менеджера и его публичную часть.
- Реестр колонок, назначения, known_hosts, квитанции установки и резервные копии.
- Токен Home Functions, пользовательские маршруты и runtime колонок.
- Метку голосовых команд HA и существующие aliases сущностей.
- Исходные адреса backend, чтобы можно было откатить перенос.

## Порядок

1. Сохраните резерв старого менеджера и работающих runtime. Не публикуйте архив.
2. Установите приложение параллельно. Укажите прежний voice_command_label и
   нужные device_labels. Пока не выполняйте установку поверх старых мостов.
3. Остановите новый менеджер перед переносом состояния и ключей в его `/data`.
4. Импортируйте данные с проверкой схемы и прав, сохранив установочные квитанции.
5. Перенесите токен Home Functions и сформируйте runtime для нового URL.
6. На одной колонке транзакционно смените backend, проверьте health, синхронизацию,
   голос и журнал. При ошибке верните прежний runtime.
7. Повторите для остальных. Старые сервисы отключайте после проверки всех колонок.

Приложение поддерживает однократный офлайн-импорт в ПУСТОЙ реестр. Архив
`/config/import.tar` должен иметь права 0600 и содержать только `state/`,
`ssh/id_ed25519`, `ssh/id_ed25519.pub`, `functions.token` и, при необходимости,
`existing-startup-sha256.json`. `/config` — каталог конфигурации этого приложения,
доступный администратору через app_configs; это не каталог конфигурации HA Core.

Импорт выполняется до запуска сервисов. Проверяются пути, типы файлов, размер,
ID колонок, назначения, токен и пара SSH-ключей. Исходные пустые данные сохраняются
в приватном `/data/migration-before`. После успеха входной архив удаляется,
а в `/data/migration.complete.json` сохраняется квитанция. Повторный импорт
других данных блокируется. Архив не должен попадать в Git или публичную Wiki.

Импорт не переключает backend на колонках. Этот шаг выполняется отдельно,
последовательно, с резервом runtime и проверкой health/синхронизации/голоса.
