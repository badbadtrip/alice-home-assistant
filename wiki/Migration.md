# Переход со старого моста

Этот раздел нужен, если на колонке остался мост от прежнего менеджера.
Добавление SSH-ключа разрешает вход, но не переносит настройки старого моста.

## Рекомендуемый способ: кнопка в мастере

Для поддерживаемого старого моста Git, Python и архив не нужны. Можно использовать
уже добавленные вручную колонки — их названия, комнаты, медиаплееры и назначения
сохранятся.

- Откройте «Настройки колонки → Мост».
- Укажите адрес приложения и разрешите SSH-доступ, если это ещё не сделано.
- Выполните «Проверить подключение».
- На шаге «Мост» нажмите «Подключить существующий мост».
- Дождитесь перехода к проверке голоса. Произнесите команду и подтвердите результат
  только после проверки на слух. Если возникла проблема, нажмите «Вернуть прежний мост».

Приложение сверяет все файлы запуска с исходниками своего поддерживаемого профиля,
проверяет текущие файлы по манифесту и запуску SSH. Неизвестные версии не изменяются.
Сохраняются прежние настройки и бинарный файл, создаётся запись для последующих
обновлений. Перед переключением проверяются свободное место, настройки и новый сервер.
При неудачной проверке запуска приложение пытается восстановить прежние файлы и
проверить прежний идентификатор. Если восстановление подтвердить не удалось, мастер
показывает действие восстановления, а не сообщение об успехе.

При переходе меняются адрес и токен Home Functions, идентификатор и комната этой
колонки. Остальные настройки runtime и маршрутизация сохраняются. Мост кратковременно
перезапускается; перезагрузка всей колонки не требуется. Остальные колонки не переключаются.

После успеха нужна ручная проверка голоса. Для перехода со старого моста нет таймера
автоматического отката: кнопка «Вернуть прежний мост» доступна до подтверждения голоса.
Если приложение перезапустилось во время перехода, сначала используйте восстановление
в мастере. Не нажимайте повторно установку.

Если файлов запуска нет в поддерживаемом профиле, не создавайте доверенный список
из файлов неизвестной колонки. Потребуется разбор конкретной установки.

## Дополнительный способ: архив прежнего менеджера

Ниже — команды для переноса всего менеджера в новое ПУСТОЕ приложение. Это
альтернатива кнопке, а не обязательное продолжение автоматического перехода.
Импорт поверх непустого реестра не поддерживается: не удаляйте вручную добавленные
колонки ради импорта, используйте кнопку выше для поддерживаемого моста.
Архивный способ нужен, когда требуется перенести также ключ и реестр старого менеджера.
Старый сервер оставляйте доступным до проверки всех колонок.

## Где выполнять команды

- Старый сервер: Linux-сервер с прежним менеджером, не консоль колонки.
- Терминал HA: Terminal & SSH / Advanced SSH & Web Terminal в HA.
- Консоль колонки: SSH-сессия с приглашением `#` или `root@…`.

Не вводите команды Linux прямо в Windows PowerShell без SSH-подключения.
IP, порты, логины и пути замените своими. Выполняйте по одному блоку;
при ошибке остановитесь.

## 1. Создайте резервную копию

В HA откройте «Настройки → Система → Резервные копии» и сохраните приложение
«Алиса». Сохраните также прежний менеджер и конфигурацию привычным способом.
Запишите прежний адрес Home Functions и настройки нового приложения.

Архив перехода содержит приватный SSH-ключ и токен. Не прикладывайте его
к сообщениям и не загружайте в Git.

## 2. Создайте архив на старом сервере

Нужны Python 3 и Git. Пример рассчитан на прежний менеджер в
`/opt/alice-manager` и токен в `/opt/stacks/home-functions/.env.local`.
Если у вас другие пути, замените их. На старом сервере:

```sh
umask 077
git clone https://github.com/badbadtrip/alice-home-assistant.git alice-transition
cd alice-transition
python3 tools/export_legacy.py --manager-dir /opt/alice-manager --env-file /opt/stacks/home-functions/.env.local --output ../alice-import.tar
```

Если репозиторий уже скачан, используйте его каталог вместо повторного клонирования.
Если токен хранится отдельным файлом, используйте `--token-file /ПУТЬ/functions.token`
вместо `--env-file`.

Ожидаемый результат: `Private archive created; speakers: N`.
Утилита не меняет исходные данные, не заменяет выходной файл и не печатает секреты.
При изменении исходных файлов во время экспорта она остановится: приостановите
записи прежнего менеджера и повторите экспорт.

Проверьте архив без вывода содержимого ключей:

```sh
cd ..
ls -l alice-import.tar
tar -tf alice-import.tar
sha256sum alice-import.tar
```

В архиве нужны `state/speakers.json`, `state/assignments.json`, `state/known_hosts`,
оба SSH-ключа и `functions.token`. Сохраняются квитанции и резервные копии
из `state/`, а при наличии — прежний проверенный `existing-startup-sha256.json`.
Исторические архивы `.tar`, `.gz` и `.zip` не копируются. Не создавайте
отсутствующий проверенный файл из неизвестной колонки наугад.

## 3. Найдите новое приложение в HA

В терминале HA:

```sh
ha addons list
ls /app_configs
```

Некоторые SSH-приложения используют `/addon_configs` вместо `/app_configs`.
Если каталог недоступен, используйте Studio Code Server или Samba с доступом
к конфигурациям приложений. Не создавайте пустой `/app_configs` вручную.

Найдите slug нового приложения «Алиса». Для этого репозитория обычно используется
`059abbae_alice`; локальная установка может называться иначе. Проверьте выбор:

```sh
ALICE_APP=059abbae_alice
ha addons info "$ALICE_APP"
```

Убедитесь, что выбрали новое пустое приложение. Остановите только его:

```sh
ha addons stop "$ALICE_APP"
```

## 4. Передайте архив в HA

На старом сервере, из каталога с `alice-import.tar`, выполните блок ниже.
Замените адрес HA, SSH-порт и логин. Нужен порт SSH-приложения HA,
не порт 8123 и не SSH-порт колонки.

```sh
HA_HOST=192.168.10.10
HA_SSH_PORT=22
HA_USER=root
scp -P "$HA_SSH_PORT" alice-import.tar "$HA_USER@$HA_HOST:alice-import.tar"
```

Если `scp` недоступен, передайте файл через закрытый Samba-ресурс.
В терминале HA проверьте файл и сумму:

```sh
ls -l "$HOME/alice-import.tar"
sha256sum "$HOME/alice-import.tar"
```

Сумма должна совпасть с показанной на старом сервере. Если SSH-сервер сохранил
файл в другом домашнем каталоге, укажите фактический путь. Затем в терминале HA:

```sh
ALICE_APP=059abbae_alice
APP_CONFIG="/app_configs/$ALICE_APP"
test -d "$APP_CONFIG" && test -f "$HOME/alice-import.tar" && test ! -e "$APP_CONFIG/import.tar" && cp "$HOME/alice-import.tar" "$APP_CONFIG/import.tar" && chmod 600 "$APP_CONFIG/import.tar"
ls -l "$APP_CONFIG/import.tar"
```

При имени `/addon_configs` исправьте `APP_CONFIG`. Если файл не появился или
команда вернула ошибку, не запускайте приложение. Не перезаписывайте уже
существующий `import.tar`.

## 5. Запустите и проверьте импорт

В терминале HA:

```sh
ha addons start "$ALICE_APP"
ha addons logs "$ALICE_APP"
```

В браузере откройте приложение. Колонки, назначения и публичный ключ должны
соответствовать прежнему менеджеру. До проверки не нажимайте установку.
После успешного импорта `import.tar` удаляется самим приложением.

Проверяются пути архива, размеры, реестр, назначения и пара SSH-ключей.
Исходные пустые данные сохраняются в приватном `/data/migration-before`,
результат — в `/data/migration.complete.json`. Это пути внутри приложения,
не в терминале SSH-приложения. Повторный импорт другого архива заблокирован.

Если журнал сообщает «Импорт разрешён только в пустой реестр», остановитесь.
Не удаляйте реестр и квитанции из терминала. Вернитесь к выбору случая в начале.
Если приложение не запускается, остановите его и восстановите резервную копию в HA.

## 6. Переключайте колонки по одной

Импорт переносит данные менеджера, но не меняет адрес сервера на колонке.
В настройках приложения укажите новый локальный адрес Home Functions и сохраните.
Для первой колонки в мастере «Мост» проверьте SSH и запустите разрешённое обновление.
Оно использует проверенные данные прежней установки и создаёт резерв.

Если снова появляется сообщение о старом мосте, проверенных данных недостаточно.
Остановитесь: не обходите проверку и не заменяйте вручную `runtime.env`.
Универсальная команда замены адреса для разных прошивок и версий не поддерживается.

На первой колонке произнесите тестовую команду. Проверьте ответ, громкость,
обычную работу Алисы и журнал нового приложения. Подтвердите голосовую проверку
только после проверки на слух. Затем переходите к следующей колонке.
Старые сервисы отключайте после успешной проверки всех колонок.

## Если нужно вернуться назад

Оставьте старый сервер доступным до завершения перехода. При проблеме используйте
резервную копию приложения в HA и предусмотренное восстановление моста.
Импорт не проверяет физический звук: последний шаг выполняет пользователь.
